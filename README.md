# Mini Booking

Небольшое приложение для бронирования одной переговорной по часовым слотам. Backend — Laravel, frontend — Vue 3 и PrimeVue. Локально используется SQLite, на бесплатном хостинге — PostgreSQL.

## Требования

- PHP 8.3+
- Composer 2
- Node.js 20.19+
- npm 10+
- расширение PHP `pdo_sqlite`

## Запуск backend

```bash
cd backend
composer install
cp .env.example .env
touch database/database.sqlite
php artisan key:generate
php artisan migrate --seed
php artisan serve
```

API будет доступно по адресу `http://127.0.0.1:8000`.

## Запуск frontend

Во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Страница будет доступна по адресу `http://127.0.0.1:5173`. Vite проксирует запросы `/api` на Laravel по адресу `http://127.0.0.1:8000`.

## Запуск через Docker

Для запуска frontend, backend и SQLite одной командой:

```bash
docker compose up --build
```

Приложение будет доступно по адресу `http://127.0.0.1:8080`. База хранится в Docker volume `booking-data` и не удаляется при перезапуске контейнера.

## Бесплатный публичный хостинг

Рекомендуемая схема для демо — Render Free для приложения и Neon Free для PostgreSQL. SQLite для Render не подходит: файловая система бесплатного сервиса очищается при остановке или новом деплое.

1. Создайте бесплатный проект на [Neon](https://console.neon.tech/) и скопируйте connection string базы данных.
2. Загрузите репозиторий в GitHub.
3. В [Render Dashboard](https://dashboard.render.com/) выберите **New → Blueprint** и подключите репозиторий.
4. Render прочитает `render.yaml`. В поле `DB_URL` вставьте connection string из Neon.
5. Запустите деплой. Миграции и сидер выполнятся автоматически, а frontend и API будут доступны на одном `onrender.com`-адресе.

На бесплатном тарифе Render усыпляет сервис после 15 минут без запросов. Первый запрос после простоя может открываться около минуты; данные при этом остаются в Neon.

## Тесты

```bash
cd backend
php artisan test
```

Тесты проверяют успешное создание бронирования и ответ `409 Conflict` на повторную попытку занять тот же слот.

## API

- `GET /api/slots` — список слотов по возрастанию времени;
- `POST /api/bookings` — создание бронирования;
- `DELETE /api/bookings/{id}` — отмена бронирования.

## Целостность данных

Отмена хранится в поле `bookings.cancelled_at`. Частичный уникальный индекс `bookings_one_active_per_slot` запрещает базе создать больше одной записи с одинаковым `slot_id` и пустым `cancelled_at`. Поэтому при одновременной вставке побеждает только один запрос, а нарушение уникальности преобразуется в `409 Conflict`.

Сидер использует `insertOrIgnore` вместе с уникальным индексом по `slots.start_at`. Повторный запуск за тот же период не меняет существующие слоты и бронирования, а запуск в другой день добавляет недостающие даты.

## Время

Расписание строится в часовом поясе `APP_TIMEZONE` из `.env` (`UTC` по умолчанию). В базе время слотов хранится как локальное время этого пояса. API возвращает ISO 8601 со смещением и отдельно передаёт название часового пояса; frontend использует его при форматировании дат и времени.

Незавершённых пунктов нет.
